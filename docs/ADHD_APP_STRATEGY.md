# nagi ADHD特化アプリ戦略書

## Executive Summary

nagiをADHD向け世界No.1のタスク管理アプリにするための戦略。
現状の多機能なWebアプリから、**ADHD脳に最適化されたモバイルファーストのAIパートナー**へ進化させる。

核心的な洞察: **ADHDの人が最も苦手なのは「管理すること」自体。だから、管理ツールではなく「管理してくれる存在」を作る。**

---

## 0. 現状分析：率直な問題提起

### nagiの現在地
- 52以上のAIツール、20近い機能モジュール
- プロジェクト管理、Ganttチャート、KPI、チーム協業、会議管理...
- Clean Architecture + Repository Pattern による堅牢な設計

### 根本的な矛盾
**ADHDの人のためのアプリなのに、ADHDの人が使いこなせない複雑さを持っている。**

これはよくある罠で、「ADHDの課題を全部解決しよう」として機能を足していった結果、
認知負荷の高いツールが出来上がってしまう。ADHDの人が最初に離脱するのは
「設定画面が多い」「何をすればいいかわからない」「画面が情報過多」な瞬間。

### 競合の状況
ADHD向けアプリ市場は急成長中だが、真の意味で「AIネイティブ」なものはまだない：

| アプリ | 強み | 弱み |
|--------|------|------|
| **Goblin Tools** | AIタスク分解がバイラル | 単機能、継続的な管理はできない |
| **TickTick** | カレンダー+ToDo+ポモドーロ統合 | ADHDに特化していない |
| **Hero** | オールインワン、無料 | AI活用が限定的 |
| **Morgen** | タイムブロッキング、容量管理 | ADHD特化ではない |
| **Recallify** | 音声→タスク化が秀逸 | タスク管理自体は弱い |
| **Habitica** | ゲーミフィケーション | AIなし、設定が重い |
| **RoutineFlow** | ゲーミフィケーション+時間盲目分析 | 新興、エコシステム不足 |

**チャンス**: AIがタスクを「自律的に管理してくれる」アプリは存在しない。
全てのアプリは「ユーザーが管理する」前提。nagiの「自律型秘書」コンセプトは本質的に正しい。

## 1. コスト戦略・販売戦略

### 1.1 AIコストの現実

Gemini 2.0 Flashの場合（2026年現在の概算）:
- 入力: ~$0.10/1M tokens
- 出力: ~$0.40/1M tokens
- 1回のチャットインタラクション（プロンプト+ツール呼び出し含む）: 約$0.002〜$0.01
- ヘビーユーザー（1日20回対話）: 月$1.2〜$6.0
- 音声文字起こし・画像処理を含むと: 月$3〜$10

### 1.2 推奨価格モデル：「ハイブリッドサブスクリプション」

2025-2026年のSaaSトレンドとして、**ハイブリッド型**（基本サブスク + 使用量連動）が主流。
ただし、ADHD向けアプリで複雑な従量課金は**絶対にNG**。
「今月あと何回使えるか」を考えさせること自体がADHDの敵。

#### Free Tierのコスト戦略

個人開発者の投資体力を考慮した現実的な選択肢：

```
★推奨: ハイブリッドモデル切替方式
  ・基本は格安モデル（Flash-Lite等）で無制限対応
    → タスク追加・完了・簡単な質問は十分な品質
  ・重要処理のみ高性能モデル（1日3回）
    → Top3推薦、タスク分解、感情対応、週次振り返り
  ・コスト: 月¥20-40/ユーザー
  ・ユーザーにはモデル切替を見せない（体験は一貫）
  ・「今日は使えません」を絶対に言わない設計
    → ADHDの人は「思いついた瞬間に捕まえる」ことが最重要

代替案: 7日間無料トライアル（Free Tierなし）
  ・全機能を7日間体験 → 有料へ
  ・コスト最小だが、ADHDの人は「7日以内に判断」が苦手
  ・投資体力がなければこちらも現実的
```

**重要**: 「あと何回使える」表示はしない。制限に達した場合もnagiが対話の中で自然に伝える。

#### 価格設定の根拠

## 2. 非テック層へのエンゲージメント戦略

### 2.1 核心的な洞察

Claude Codeを使える人はすでにAIでタスク管理できる。
しかし**ADHDの人口の99%はそういう人ではない**。

ADHD当事者のペルソナ：
- 30代会社員、診断済みまたはグレーゾーン
- スマホは使えるが、テクノロジーに詳しくない
- これまで10個以上のToDoアプリを試して全部挫折
- 「またダメかも」という学習性無力感がある
- 設定画面を見た瞬間にやる気を失う

### 2.2 「ゼロコンフィグ」設計原則

**初回起動から価値提供まで30秒以内**

```
┌──────────────────────────────────────┐
│          nagiへようこそ               │
│                                      │
│   あなたの名前を教えてください         │
│   ┌────────────────────────┐         │
│   │                        │         │
│   └────────────────────────┘         │
│                                      │
│   「はじめる」                        │
└──────────────────────────────────────┘
          ↓（名前入力のみ）
┌──────────────────────────────────────┐
│                                      │
│   こんにちは、○○さん。               │
│   nagiです。あなたの秘書をします。     │
│                                      │
│   何か気になっていることや、            │
│   やらなきゃと思っていること、          │
│   なんでも話してください。             │
│                                      │
│   🎙️ [話しかける]  ⌨️ [書く]          │
│                                      │
└──────────────────────────────────────┘
```

- 設定画面なし
- チュートリアルなし
- 「いきなり話せる」体験
- nagiが対話の中でプロフィールを学習していく

### 2.3 エンゲージメントの3層構造

#### Layer 1: 即時価値（初日）
- 音声で「あれやらなきゃ」と言うだけでタスク化される
- nagiが「今日はこの3つをやりましょう」と提案してくれる
- 「やったよ」と言うだけで完了できる
- **体験する感情: 「え、これだけでいいの？楽すぎる」**

#### Layer 2: 習慣化（1週間）
- 朝の「おはようございます。今日の予定は〜」通知
- 夕方の「今日もお疲れさまでした。明日は〜」通知
- タスク完了時の「さすがです！」の一言
- 少しずつユーザーの行動パターンを学習
- **体験する感情: 「nagiがいると安心する」**

#### Layer 3: 依存→信頼（1ヶ月）
- 「来週の○○の件、そろそろ準備しません？」と先回り
- 「最近、午前中に集中できてますね」とフィードバック
- 月次の振り返り「今月は○個のタスクを達成しました」
- **体験する感情: 「nagiは本当に自分のことをわかってくれる」**

### 2.4 リテンション戦略

ADHD向けアプリの最大の課題は**継続率**。
ADHDの人は「飽きる」「忘れる」「新しいものに飛びつく」。

対策：
1. **プッシュ通知の最適化** — 多すぎると切られる。少なすぎると忘れられる。nagiが学習して最適な頻度を見つける
2. **「見捨てない」設計** — 3日使わなくても「久しぶりですね。溜まったタスク、一緒に整理しましょうか？」と復帰を促す
3. **感情への寄り添い** — 「今日はやる気が出ないんだね。それでもOK。1個だけやってみない？」
4. **成長の可視化** — 週次・月次で「あなたの成長」を見せる（ADHDの人は自己評価が低いため、客観的な成果を見せることが重要）

## 3. シンプル化戦略

### 3.1 現状の問題

現在のnagiの機能を全て並べると：

```
タスク管理 / サブタスク / 依存関係 / プロジェクト管理 / フェーズ /
マイルストーン / KPI / Ganttチャート / カンバンボード / チーム管理 /
メンバー招待 / 権限管理 / 会議管理 / アジェンダ / 議事録 /
リカーリングタスク / スケジュール管理 / キャパシティ管理 /
チェックイン / 実績管理 / メモリーシステム / ブラウザ自動化 /
Chrome拡張 / 課題管理 / ダッシュボード / ...
```

これは**ADHD当事者が見た瞬間に閉じる量**。

### 3.2 「デフォルトシンプル、いつでも拡張」設計

~~たまねぎ構造（段階的アンロック）~~ → **撤回**。
ゲームの機能アンロックのような設計はADHD向けアプリとして不適切。
「プロジェクト管理がしたくてインストールしたのに1週間待たされる」はストレスでしかない。

**新方針: 機能は最初から全部ある。ただしデフォルト表示はシンプル。**

```
┌──────────────────────────────────────────────┐
│                                              │
│   デフォルト表示（初期状態）                    │
│   ┌────────────────────────────────────┐     │
│   │ ・チャット（音声/テキスト）          │     │
│   │ ・今日のTop3                        │     │
│   │ ・タスクリスト（シンプル表示）        │     │
│   └────────────────────────────────────┘     │
│                                              │
│   [+ 機能を追加] ← 1タップで有効化            │
│   ┌────────────────────────────────────┐     │
│   │ ☐ プロジェクト管理                   │     │
│   │ ☐ スケジュール管理                   │     │
│   │ ☐ 繰り返しタスク                     │     │
│   │ ☐ カンバンボード                     │     │
│   │ ☐ チーム機能 (Premium)               │     │
│   │ ☐ 会議管理 (Premium)                 │     │
│   │ ☐ ...                               │     │
│   │                                      │     │
│   │ （いつでも変更できます）               │     │
│   └────────────────────────────────────┘     │
│                                              │
└──────────────────────────────────────────────┘
```

**設計原則:**
- デフォルトはシンプル → 情報過多による初回離脱を防ぐ
- 全機能にすぐアクセス可能 → 目的を持って来た人を邪魔しない
- ユーザーが自分で選ぶ → 自律性の尊重（Slack「チャンネルを追加」と同じパターン）
- いつでもオン/オフ切替可能 → 「とりあえず全部オン」しても後から減らせる

### 3.3 モバイルUIの設計原則

#### 画面数を最小化

```
メイン画面（3つだけ）:

┌────────┬────────┬────────┐
│        │        │        │
│  今日   │ チャット │ 振り返り │
│        │        │        │
└────────┴────────┴────────┘

「今日」画面:
┌──────────────────────────┐
│  おはようございます、○○さん │
│  今日やること:              │
│                            │
│  ☐ 1. 企画書の下書き (30分)  │
│  ☐ 2. Aさんに返信 (5分)     │
│  ☐ 3. 資料の確認 (15分)     │
│                            │
│  ──────────────────────── │
│  あとでやること (3件) ▼      │
│                            │
│  🎙️ [nagiに話す]           │
└──────────────────────────┘
```

#### デザインの4原則
1. **1画面1アクション** — 画面に表示する選択肢は最大3つ
2. **色は2色** — メインカラー + アクセントカラーのみ
3. **文字は大きく** — 最小フォントサイズ16px
4. **余白を恐れない** — 情報密度より認知的快適さ

### 3.4 削る勇気：v1で捨てるもの

モバイルアプリv1では以下を**意図的に含めない**：

| 機能 | 理由 |
|------|------|
| Ganttチャート | 認知負荷が高すぎる。ADHDには不向き |
| KPI管理 | 企業向け機能。個人には不要 |
| カンバンボード | 「管理してる感」が出すぎる |
| チーム機能 | v1は個人に集中 |
| 会議管理 | v1は個人のタスクに集中 |
| Chrome拡張 | モバイルでは不要 |
| ブラウザ自動化 | パワーユーザー向け |
| 権限管理 | 個人アプリに不要 |
| フェーズ/マイルストーン | 複雑すぎる。nagiが内部的に使う |

**これらは「削除」ではなく「隠す」。** バックエンドには残し、将来のPremiumプランやWeb版で提供。

## 4. 差別化戦略

### 4.1 既存ToDoアプリとの根本的な違い

```
既存のToDoアプリ:
  ユーザー → [タスクを入力] → [管理する] → [実行する]
                  ↑人間の意志力に依存↑

nagi:
  ユーザー → [つぶやく/話す] → nagi が管理 → [nagiが促す] → 実行
                  ↑ゼロ意志力↑     ↑自律的↑      ↑最適タイミング↑
```

### 4.2 5つの差別化軸

#### 差別化1: 「管理しなくていい」タスク管理
- 他のアプリ: ユーザーがタスクを整理・優先順位付け・スケジューリングする
- nagi: **nagiが全部やる。ユーザーは「やったよ」と言うだけ**
- タグ付け、優先度設定、カテゴリ分け → 全部AIが裏でやる
- ユーザーに見せるのは「今日やること3つ」だけ

#### 差別化2: 「感情を理解する」AI
- 他のアプリ: タスクの期限とステータスだけを管理
- nagi: **ユーザーの感情状態を理解してアプローチを変える**
  - 「やる気が出ない」→ 最も簡単なタスク1つだけ提案
  - 「過集中してた」→ 休憩を促す
  - 「全部やらなきゃ」→ 「大丈夫、3つだけで十分」と安心させる
- ADHD特有の感情（拒絶敏感性、完璧主義、自己否定）に対応

#### 差別化3: 「音声ファースト」の入力
- 他のアプリ: テキスト入力が基本
- nagi: **話すだけでOK**
  - 「あ、そういえば来週の金曜に歯医者だ」→ 自動でタスク化+リマインド設定
  - 「今日の会議の資料、あの件も入れなきゃ」→ 既存タスクに追記
  - 「もう無理、全部忘れた」→ 「大丈夫です。整理しましょう」+現状サマリー
- ADHDの人は「思いついた瞬間に捕まえる」ことが最重要

#### 差別化4: 「見捨てない」リテンション
- 他のアプリ: 使わなくなったらそのまま放置
- nagi: **3日間使わなくても「お元気ですか？」と声をかける**
  - 復帰のハードルを下げる（「溜まったタスク、一緒に整理しよう」）
  - 罪悪感を与えない（「休んでたんですね。それも大事です」）
  - ADHDの「all or nothing」思考に対抗

#### 差別化5: 「成長を見せる」フィードバック
- 他のアプリ: 完了率やストリークを表示（途切れると逆効果）
- nagi: **「あなたは思ってる以上にやれてる」を証明する**
  - ストリークは使わない（途切れた瞬間に離脱するため）
  - 代わりに「今月は先月より2個多くタスク完了しましたよ」
  - 「3ヶ月前は5分のタスクも手をつけられなかったのに、今は30分のタスクもこなせてます」
  - ADHDの人の最大の敵は「自分はダメだ」という思い込み

### 4.3 ポジショニングマップ

```
        AI活用度 高
            │
            │         ★ nagi
            │        （AI自律管理）
            │
            │    Recallify
            │    （AI音声→タスク）
            │
            │ Goblin Tools
            │（AI分解のみ）
    ────────┼────────────────── ADHD特化度
   汎用     │             高
            │
   TickTick │    Hero
   Todoist  │    Habitica
   Notion   │    RoutineFlow
            │
            │
        AI活用度 低
```

nagiは「AI活用度 × ADHD特化度」の両方で最も高いポジションを目指す。

## 5. 追加提案：あなたが言及していない重要な論点

### 5.1 モバイル技術選定

| 選択肢 | メリット | デメリット | 推奨度 |
|--------|---------|-----------|--------|
| **React Native** | Web版のReact資産を活かせる、1コードで iOS/Android | ネイティブ性能に劣る場面あり | ★★★★☆ |
| **Flutter** | 高性能UI、Google製でGeminiとの親和性 | Dart学習コスト、既存コード活かせない | ★★★☆☆ |
| **PWA** | 最も早くリリース可能、既存Web版を活用 | プッシュ通知制限(iOS)、ストア配布しにくい | ★★★☆☆ |
| **Expo (React Native)** | 最も開発速度が速い、OTAアップデート | ejectionが必要な場面あり | ★★★★★ |

**推奨: Expo (React Native)**
- 既存のReact + TypeScriptの資産を最大限活用
- OTAアップデートで素早いイテレーション
- iOS/Android同時リリース
- プッシュ通知のフルサポート

### 5.2 ブランディング戦略

「nagi」という名前は日本語圏では良いが、グローバル展開を考えると：

- **日本市場先行**: 「nagi」のまま。「凪」= 心の平穏、というブランドストーリー
- **「ADHDの人のための」を前面に出す** — 恥ずかしさではなく誇りとして
- **キャッチコピー案**:
  - 「もう、全部覚えなくていい。」
  - 「あなたの脳の相棒。」
  - 「忘れても、大丈夫。nagiが覚えてる。」

### 5.3 データとプライバシー

ADHD当事者のデータは極めてセンシティブ：
- 医療情報に準じる扱いが必要
- 「ADHDの人が使っている」こと自体がプライバシー
- **必須対応**:
  - エンドツーエンド暗号化（少なくともメモリ・チャット履歴）
  - データの所在地選択（日本国内保持オプション）
  - 「全データ削除」機能の提供
  - プライバシーポリシーを平易な言葉で
  - ADHD等の診断情報は収集しない

### 5.4 法規制・医療との境界

- nagiは**医療機器ではない**ことを明確にする
- 「ADHDを治す」「症状を改善する」等の表現は薬機法に抵触する可能性
- 正しいフレーミング: 「日常のタスク管理をサポートする」「生産性を支援する」
- 医療専門家の監修を受けることで信頼性向上

### 5.5 コミュニティ戦略

ADHD当事者コミュニティは非常に結束が強い：
- 「これ良かった」の口コミが最強のマーケティング
- 当事者のフィードバックを開発に直接反映（Issue Boardは良い機能）
- 「ADHDの人が作った、ADHDの人のためのアプリ」というストーリー
- Discord/LINEコミュニティの運営
- ベータテスター制度（ADHD当事者限定）

## 8. まとめ：勝つための3つの鉄則

### 鉄則1: 「機能の数」ではなく「認知負荷の低さ」で勝負する
Notionは100の機能がある。nagiは3つの画面しかない。でもnagiの方がADHDの人の人生を変える。

### 鉄則2: 「ツール」ではなく「存在」を作る
nagiは道具ではない。「自分のことをわかってくれる秘書」という関係性を作る。だからユーザーは離れない。

### 鉄則3: 「全員向け」ではなく「ADHD向け」に振り切る
「誰でも使える」アプリは誰にも刺さらない。「ADHDの人のために作った」と明言することで、当事者の心に刺さる。
